# P02 — Create database, migrations and atomic command handling

PDF phase: 1. Dependencies: P01.
Requirements: PDF §§17,20; D03,D04,D09.

## Instructions

Read ../PROMPT_BOOK.md's shared execution contract, ../PROGRESS.md and ../HANDOFF.md. Inspect actual code and adopted TARGET_SPEC.md before editing. Proposed paths may not exist yet. Implement only this task.

Primary ownership: backend/v2/db; migrations; dependencies/config; integration tests.

1. Implement schema blueprint in ARCHITECTURE.md using SQLAlchemy/Alembic. Foreign keys, uniqueness, run/date keys and version checks belong in the DB. Do not use a serialized v1 world blob as the target relational model.
2. Implement unit of work, command deduplication with payload hash, audit, scheduled event uniqueness and transactional outbox. Configure local SQLite WAL, foreign keys and bounded busy timeout; no ORM session shared across threads.
3. Add consistent backup/restore and migration tests. Establish one prototype scheduler owner. Preserve committed operations across a fresh process; route and inference jobs cannot run inside transactions.

## Acceptance

Empty/upgrade migrations pass; duplicate commands have one effect; changed-payload key reuse conflicts; crash before/after commit preserves atomicity; no startup reset of v2.

Use ../ACCEPTANCE.md for named test vectors. Record exact commands, environment, output and remaining uncertainty. Run relevant existing regressions as well as behavior tests. Do not treat a build or mocked provider as full integration evidence.

## Handoff

Update ../PROGRESS.md and ../HANDOFF.md after this task and before stopping. Record files, migrations, decisions, verification, next action and any partial work. Only mark done when every acceptance item passes. No public deployment, external messages, destructive data reset or claims that later tasks are implemented.
